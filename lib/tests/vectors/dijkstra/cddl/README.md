# Account balance interval vectors generated from the Dijkstra CDDL

This directory holds CBOR values generated from the Dijkstra era CDDL published by
the Cardano ledger. They pin the encoding of transaction body keys 26
(`account_balance_intervals`, also allowed in a sub transaction body) and 27
(`starting_account_balance_intervals`, top level only) to the ledger schema rather
than to hand written examples. Each file holds one CBOR value per line, hex encoded,
with duplicates removed.

## Upstream source

[IntersectMBO/cardano-ledger](https://github.com/IntersectMBO/cardano-ledger),
`eras/dijkstra/impl/cddl/data/dijkstra.cddl`

Commit: `9df9f98cce86c5f2195142b2c02dd9b39dd9dc7c`

The rules exercised here are:

```
account_balance_intervals = {+ reward_account => account_balance_interval}

starting_account_balance_intervals =
  {+ reward_account => account_balance_interval}

account_balance_interval =
  [inclusive_lower_bound : coin, exclusive_upper_bound : coin/ nil]
  / [inclusive_lower_bound : coin/ nil, exclusive_upper_bound : coin]
  / coin

coin = uint

reward_account = bytes
```

## Files

| File                                             | Content                                                                 |
|--------------------------------------------------|-------------------------------------------------------------------------|
| `account_balance_interval.txt`                   | 50 values of `account_balance_interval`.                                |
| `account_balance_intervals.txt`                  | 50 values of `account_balance_intervals`.                               |
| `starting_account_balance_intervals.txt`         | 50 values of `starting_account_balance_intervals`.                      |
| `account_balance_intervals_unrestricted_key.txt` | 10 values of `account_balance_intervals` with arbitrary `reward_account` bytes. |

The tests in `lib/tests/transaction_body/account_balance_interval.cpp` and
`lib/tests/transaction_body/account_balance_intervals_map.cpp` decode every value and
re-encode it.

## Tools

- cuddle 1.8.1.0, installed with `cabal install cuddle-1.8.1.0` (GHC 9.6.7, cabal-install
  3.14.1.1) in the docker image `haskell:9.6@sha256:adba20678db75a4ef90b943bc05520cb20d30837e81f7446e20817f9dcca09a7`.
- cddl 0.12.14 (Ruby gem), installed with `gem install cddl -v 0.12.14` (Ruby 3.3.13)
  in the docker image `ruby:3.3@sha256:35460b769ba5f033ccf5525d04acea2612ad471d4ca9c84ace8e9347839d421d`.

cuddle is the CDDL tool the ledger itself builds its CBOR generators on, and it is
used on the published CDDL without changes. It cannot parse the `.cat` control
needed to restrict reward accounts (see below), so the two map files are generated
with the Ruby cddl tool instead, and every value it generates is validated against
the unmodified published CDDL before it is written.

## Reward accounts

The CDDL declares `reward_account = bytes`, but the ledger decodes the key with
`fromCborAccountAddress` (libs/cardano-ledger-core/src/Cardano/Ledger/Address.hs at
the same commit), which only accepts a 29 byte value whose header satisfies
`header .&. 0b11101110 == 0b11100000`, followed by a 28 byte key or script hash.
cardano-c applies the same rule and rejects any other key with
`CARDANO_ERROR_INVALID_ADDRESS_FORMAT`.

To generate maps the ledger accepts, the map files come from a copy of the CDDL
whose `reward_account` rule is replaced by exactly that constraint:

```
reward_account = reward_account_header .cat hash28
reward_account_header = h'e0' / h'e1' / h'f0' / h'f1'
```

account_balance_intervals_unrestricted_key.txt keeps maps generated by cuddle from the
unmodified CDDL, whose keys are arbitrary bytes. The tests expect cardano-c to reject
every one of them.

## Coin width

The Ruby cddl tool draws `uint` values below 4711, so half of each map file is
generated from a second copy that also declares `coin = uint .size 8`. In CBOR an
unsigned integer always fits in 8 bytes, so this accepts the same values and only
makes the tool draw from the full 64 bit range.

## Indefinite lengths

cuddle randomly encodes arrays, maps and byte strings with indefinite lengths, which
the CDDL allows. Some interval values are therefore indefinite length arrays (`9f`
... `ff`). cardano-c accepts them and writes the equivalent definite two element
array, so the round trip test expects those values back with a definite header.
The Ruby cddl tool only emits definite lengths, so the map files round trip byte for
byte.

## Regenerating

From an empty directory holding `dijkstra.cddl` copied from the commit above:

```sh
awk '/^reward_account = bytes$/ { print "reward_account = reward_account_header .cat hash28"; print "reward_account_header = h'"'"'e0'"'"' / h'"'"'e1'"'"' / h'"'"'f0'"'"' / h'"'"'f1'"'"'"; next } { print }' dijkstra.cddl > generate-narrow.cddl
sed "s/^coin = uint$/coin = uint .size 8/" generate-narrow.cddl > generate-wide.cddl

docker run --rm -v "$PWD":/w -w /w haskell:9.6@sha256:adba20678db75a4ef90b943bc05520cb20d30837e81f7446e20817f9dcca09a7 sh -c 'cabal update && cabal install cuddle-1.8.1.0 --installdir=/usr/local/bin && sh generate-cuddle.sh'
docker run --rm -v "$PWD":/w -w /w ruby:3.3@sha256:35460b769ba5f033ccf5525d04acea2612ad471d4ca9c84ace8e9347839d421d sh -c 'gem install cddl -v 0.12.14 && sh generate.sh'
```

`generate-cuddle.sh`:

```sh
#!/bin/sh
set -e
mkdir -p out
for seed in $(seq 1 60); do
  cuddle gen -f hex -s "$seed" account_balance_interval dijkstra.cddl 2>/dev/null | tail -n 1
  echo
done | grep . | awk '!seen[$0]++' | head -n 50 > out/account_balance_interval.txt
for seed in $(seq 1 10); do
  cuddle gen -f hex -s "$seed" account_balance_intervals dijkstra.cddl 2>/dev/null | tail -n 1
  echo
done | grep . | awk '!seen[$0]++' > out/account_balance_intervals_unrestricted_key.txt
```

`generate.sh`:

```sh
#!/bin/sh
set -e
mkdir -p out
generate() {
  { ruby gen.rb generate-narrow.cddl "$1" 25 "$2"; ruby gen.rb generate-wide.cddl "$1" 25 "$3"; } 2>/dev/null | awk '!seen[$0]++' > "out/$1.txt"
}
generate account_balance_intervals 1 2
generate starting_account_balance_intervals 3 4
```

`gen.rb` seeds Ruby's generator and routes the tool's byte source through it, so the
output is reproducible:

```ruby
require 'cddl'
source, rule, count, seed = ARGV[0], ARGV[1], Integer(ARGV[2]), Integer(ARGV[3])
srand(seed)
Random.define_singleton_method(:new) { |*| Random }
generator = CDDL::Parser.new("vector = #{rule}\n" + File.read(source))
validator = CDDL::Parser.new("vector = #{rule}\n" + File.read('dijkstra.cddl'))
seen = {}
count.times do
  value = generator.generate
  abort 'generated value does not validate' unless validator.validate(value, false)
  hex = value.to_cbor.unpack1('H*')
  next if seen[hex]
  seen[hex] = true
  puts hex
end
```
